# Key Files

Per-file notes on non-obvious behaviour, wiring decisions, and invariants.

- **`cmd/server/main.go`** — composition root. Order: logger → config (`Validate()`) → tracing + metrics → Valkey stores + ping → RP / O&M / Turnstile / hasher / Catalog / Billing clients → HandoffOrchestrator → 4 services (Session, Signup, PaidSignup `.WithRateLimits(...)`, Status) → Handlers (`.WithPaidRequestDeadline(...)`) → Router → metrics server :9090 → API server :8080 (`WriteTimeout = cfg.ServerWriteTimeout()`; gincommon `RequestTimeout = cfg.MaxRequestDeadline()`) → shutdown (30 s budget): API drain → metrics server → Valkey close → tracing → gincommon. A missing required env var (`VALKEY_URL`, `SBFF_HMAC_KEY`, `SBFF_TURNSTILE_SECRET`, `REALM_PROVISIONER_BASE_URL`, `ORG_MEMBERSHIP_BASE_URL`, `CAPTCHA_SITE_KEY`) panics; an invalid one makes `Validate()` fail and the process exit 1 (e.g. `PBKDF2_ITERATIONS < 210000`, `BILLING_TIMEOUT_MS < 15000` with paid on). The `staticCatalog` fallback is used when `CATALOG_BASE_URL` is empty. `defaultIDGen` uses oklog/ulid for `signup_id` (ULID) and google/uuid v7 for `tenant_id` (UUIDv7).

- **`cmd/server/wiring.go`** — client factories. `buildBilling()` returns the B-I1 HTTP adapter when `PAID_SIGNUP_ENABLED=true` and `BILLING_BASE_URL` is set, else `port.BillingStub`. `buildTurnstile()` returns a no-op verifier only with `CAPTCHA_SKIP=true`.

- **`internal/config/config.go`** — all configuration from env vars, with `Validate()` called before any connection. With paid signup on, `Validate()` requires `BILLING_BASE_URL`, `BILLING_TIMEOUT_MS >= MinBillingTimeoutMs` (15000) and `PAID_REQUEST_DEADLINE_MS >= BILLING + RP + I1 timeouts`. `MaxRequestDeadline()` (longest handler deadline) drives gincommon's `RequestTimeout`; `ServerWriteTimeout()` is that + 500 ms; `HandoffLockTTL()` is that + 5 s (≥ 15 s). Separate `RP_TIMEOUT_MS` (RP-1, 2000) and `RP2_TIMEOUT_MS` (RP-2, 8000); `Validate()` checks the trial and paid deadlines cover their call chains. `PasswordPolicy()` and `SlugRules()` return the fixed domain structs used in SB-1 and SB-2. The password policy here is the **only** enforcement at signup — Keycloak cannot re-check a pre-hashed credential (LLD §10.6, C-4). If Keycloak's trial realm policy ever changes, this config must change in the same release.

- **`internal/core/domain/errors.go`** — sentinel errors + `DomainError{Cause, Message, Details}`. HTTP mapping lives in `adapter/inbound/http/errors.go`. Always use `errors.As(err, &de)` to unwrap; never string-match on `.Error()`.

- **`internal/core/domain/handoff.go`** — `Handoff` record (Valkey §4.2) and `HandoffState` with 10 states. Trial: `allocated → identity_created`. Paid: `payment_pending ⇄ payment_action_required → payment_confirmed → identity_created`. Shared: `identity_created → completed / tenant_pending / slug_conflict`; `tenant_pending → completed / failed`; `slug_conflict → identity_created` (SB-4). `rejected` is declared but never set (rejections delete the handoff). Gates: `IsTerminal()`, `IsPaymentResumable()`, `CanResume()`, `CanChangeSlug()`. The record also holds `Type` (trial/paid), `BillingSubscriptionID`, `PaymentRefHMAC` (HMAC of the payment token, never the token) and `LicensedSeats`.

- **`internal/core/domain/slug.go`** — `DeriveSlug` (ASCII-fold → lowercase → non-alphanumeric runs to `-` → trim → truncate to 30), `ValidateSlug` (pattern `^[a-z0-9](?:[a-z0-9-]{1,28}[a-z0-9])$`, reserved word check), `SuggestSlugs` (up to 3 alternatives for slug conflict). The BFF's slug rule is a strict subset of O&M's rule so anything BFF accepts, O&M also accepts.

- **`internal/core/domain/signup.go`** — field validators (`ValidateCompanyName`, `ValidateAdminName`, `ValidateAdminEmail`, `ValidatePassword`). `ValidatePassword` is the authoritative policy check — it is the ONLY check because the password is hashed before reaching Keycloak.

- **`internal/core/port/`** — all interfaces. Key ones: `HandoffStore` (Create/Get/Update/Delete + AcquireLock/ReleaseLock), `SessionStore` (Create/Get/Refresh/Delete), `RateLimiter` (IncrIP/IncrEmail/IncrSession/IncrPoll), `RealmProvisioner` (ProvisionTrial RP-1, ProvisionDirect RP-2), `OrgMembership` (ProvisionTenant I-1, CheckEligibility CR-4, CheckSlugFree PUB-1), `BillingClient` (AuthorizeAndCharge B-I1), `PasswordHasher` (Hash), `Catalog` (Plans). `IDGenerator` has `NewULID()` and `NewUUIDv7()` — both are on a single interface wired in `cmd/server/main.go`.

- **`internal/core/service/handoff_orchestrator.go`** — the core provisioning sequence. `Run()` = eligibility check → PUB-1 pre-check (a conflict returns `409 slug_taken` and leaves the handoff `allocated`, so a resubmit with a new slug works) → RP-1 → inline I-1 with retries. `runI1` retries I-1 up to `maxI1InlineRetries=2` with 100ms/250ms backoff; on exhaustion sets `tenant_pending` and returns (caller sends 202). `ResumeI1()` is called from SB-3 during polling — checks the 15-minute `resumeWindow` and calls `callI1Once`. `ChangeSlug()` is called from SB-4 — increments `slug_attempts` (max 5), updates the handoff slug, calls `callI1Once`. All state transitions are written to Valkey via `handoffs.Update(ctx, h)` before returning.

- **`internal/core/service/signup_service.go`** — SB-2 entry point. Sequence: step 0 same-email resume of `identity_created`/`tenant_pending`/`slug_conflict` returns before CAPTCHA (no budget used) → CAPTCHA first (SB-INV-5) → rate limits (after CAPTCHA, G-2) → validation → resubmit/resume check → hash password → allocate handoff → acquire distributed lock → persist handoff → orchestrate. `emailHMAC` uses HMAC-SHA256 with `SBFF_HMAC_KEY` so Valkey never holds a readable email. `handleResubmit` implements the G-1 resubmit matrix from LLD §5.4.

- **`internal/core/service/session_service.go`** — SB-1 (create session) and CSRF/session validation used as middleware. `ValidateCSRF` checks the session exists and the CSRF token SHA-256 matches. `hashCSRF` is SHA-256 of the token string.

- **`internal/core/service/status_service.go`** — SB-3 (poll status) and SB-4 (change slug). SB-3 acquires the distributed lock before attempting I-1 resume so concurrent polls don't race. Both SB-3 and SB-4 check that `sessionSignupID == pathSignupID` before any Valkey access — if they don't match, return `404 signup_not_found` with no hint (LLD §5.5).

- **`internal/adapter/inbound/http/router.go`** — single source of truth for routes. `requireValidatedSession` middleware does session + CSRF validation for POSTs, session-only for GETs. `middleware.RequireJSON` rejects POSTs without `Content-Type: application/json` (400); `strict_json.go` rejects unknown JSON fields; bodies over 16 KiB return 413. `noStoreHeaders()` sets `Cache-Control: no-store` and `X-Content-Type-Options: nosniff` on every response. POST routes require `ValidateOrigin` before session validation.

- **`internal/adapter/inbound/http/handlers.go`** — all 5 endpoint handlers (Session, SubmitTrial, SubmitPaid, GetStatus, ChangeSlug). SubmitTrial and SubmitPaid re-issue the session cookie (sliding TTL); SubmitPaid uses `paidRequestDeadline` and returns `202 payment_action_required` with the 3-D Secure action. `acceptLocale` derives `default_locale` from `Accept-Language` (allow-listed). Slug taken (409) is the same gincommon problem with `signup_id`/`suggestions`/`message` extension members; all other errors go through `HandleError` (`errors.go`: maps domain sentinels to gincommon problem constructors, UPPER_SNAKE `errorCode`, `Retry-After` for rate-limited and dependency-unavailable errors that carry `retry_after_seconds`; when the request context itself ended it writes nothing — gincommon's timeout middleware answers `503 REQUEST_TIMEOUT` — or records `499` for a client disconnect). No error DTOs: Swagger `@Failure` uses `ProblemResponse = problem.Problem`.

- **`internal/adapter/inbound/http/middleware/session.go`** — `SetSessionCookie` calls `c.SetSameSite(http.SameSiteStrictMode)` before `c.SetCookie` because gin defaults to `SameSite=Lax`. The cookie is re-issued on SB-2 and SB-3 so the session TTL slides. Cookie path is `/api/v1/signup`.

- **`internal/adapter/inbound/http/middleware/clientip.go`** — reads `x-envoy-external-address` set by Envoy (never parses `X-Forwarded-For` directly, LLD §10.2 N-8). Falls back to `c.ClientIP()` in local dev; `newEngine()` (`engine.go`) disables gin trusted proxies so forged `X-Forwarded-For` is ignored.

- **`internal/adapter/outbound/valkey/handoff_store.go`** — `AcquireLock` uses `SET NX PX` with the TTL from `WithLockTTL(cfg.HandoffLockTTL())` (longest request deadline + 5 s, ≥ 15 s). `ReleaseLock` uses a Lua script to atomically delete only if the token matches (prevents a slow request from releasing another request's lock). `Update` uses `completedTTL=10min` when state is `completed`, otherwise `handoffTTL=30min`.

- **`internal/adapter/outbound/realmprovisioner/client.go`** — branches on RFC 9457 `errorCode` field (never `detail`). `EMAIL_ALREADY_REGISTERED` → `ErrEmailUnavailable`. RP-1 `OPERATION_IN_PROGRESS` → `ErrOperationInProgress` (the orchestrator retries once with the same key); RP-2 `OPERATION_IN_PROGRESS` → `ErrInvalidState` (409). `INVALID_REQUEST` → `ErrInternal` (BFF bug, page).

- **`internal/adapter/outbound/orgmembership/client.go`** — `CheckEligibility` treats HTTP 200 as eligible, `409 TRIAL_ALREADY_USED` as `ErrTrialNotEligible`. `ProvisionTenant` treats HTTP 200 and 201 both as success (200 = idempotent replay). `409 SLUG_ALREADY_TAKEN` → `ErrSlugTaken`. No `Idempotency-Key` header — O&M I-1 is idempotent by state on `tenant_id` (LLD §9.2).

- **`internal/adapter/outbound/hasher/pbkdf2.go`** — PBKDF2-SHA512, 210,000 iterations, 16-byte random salt. Output is `HashedPasswordSeed` JSON — RP-1 maps this to Keycloak `secretData`/`credentialData`. Zeroes the derived key after encoding. Iteration count validated `>= 210000` in `config.Validate()`.

- **`internal/adapter/outbound/tracing/tracing.go`** — the only door to tracing, built on gincommon (`NewTracer`, `RecordSpanError`, `InjectTraceContext`); the only non-test package allowed to import OpenTelemetry (TRACES-2). `Annotate(ctx, k, v, …)` sets span attributes (IDs and states only — SB-INV-2); `StartClientSpan`; `Transport(dependency, propagate)` gives every outbound HTTP call a client span `"<METHOD> <dependency>"` and injects `traceparent` when `propagate` (false for Turnstile, a third party). The tracer is resolved per span so it always uses gincommon's current provider. `valkey/tracing.go` adds a go-redis hook: one client span per command / pipeline, never keys or arguments; `redis.Nil` is not an error.

- **`internal/adapter/outbound/catalog/client.go`** — in-process 5-minute cache with mutex. On Catalog Service failure, serves the last good copy or the static `plansFallback` from config. The fallback codes must always be exactly `starter`/`pro`/`enterprise` (never `"trial"`).

- **`deploy/helm/`** — Helm chart with `values-{dev,staging,prod}.yaml`. NetworkPolicy ingress: only `envoy-gateway-system` (API port 8080) and `monitoring` (metrics port 9090). HPA is CPU-only (PBKDF2 is CPU-bound; RPS-based scaling needs a custom-metrics adapter). PDB `minAvailable: 1`. ServiceEntry for Turnstile is off by default — enable in prod if mesh uses `REGISTRY_ONLY`.

- **`internal/core/port/billing.go`** — `BillingClient` port for B-I1. `ChargeResponse.Outcome` is `ChargeConfirmed` (zero value) / `ChargeActionRequired` (+ `Action{Type, ClientSecret}`, `ExpiresAt`) / `ChargeAlreadyExists`. Errors: `ErrPaymentDeclined` (+ `decline_reason`), `ErrChargeExpired`, `ErrDependencyUnavailable` (retry with the same key and body; may carry `retry_after_seconds`), `ErrValidationFailed` / `ErrInternal`. `BillingStub` is wired only when `PAID_SIGNUP_ENABLED=false`. Key format `"charge:<tenant_id>"`.

- **`internal/adapter/outbound/billing/client.go`** — B-I1 `POST /api/v1/internal/subscriptions/authorize-and-charge`. Sends only `x-tenant-id` and `Idempotency-Key` (caller identity = mesh SPIFFE ID); body `tenant_id`, `plan_code`, `licensed_seats`, `payment_method_ref` (required fields only, so retries repeat the body). Maps `201`/`200` → confirmed; `402 PAYMENT_ACTION_REQUIRED` → action required; `402 PAYMENT_DECLINED` → `ErrPaymentDeclined` (unknown `decline_reason` → `"other"`); `410 CHARGE_EXPIRED`; `409 SUBSCRIPTION_ALREADY_EXISTS` → already-exists outcome; `409 REQUEST_IN_PROGRESS` and `500/502/503/504` → retryable (`Retry-After` delta-seconds → `retry_after_seconds`); `422 PRICE_NOT_AVAILABLE` → `ErrValidationFailed`; `400`/`403`/other → `ErrInternal`.

- **`internal/core/port/realm_provisioner.go`** — now owns both RP-1 (`ProvisionTrial`) and RP-2 (`ProvisionDirect`). `ProvisionDirectRequest` mirrors `ProvisionTrialRequest` plus `BillingSubscriptionID`; re-confirm the RP-2 field set against RP LLD §5.3 before paid go-live (LLD §19.6). RP-2 returns `keycloak_user_id` (used) and `email_verification_sent` (not read yet).

- **`internal/core/service/paid_signup_service.go`** — SB-5 (LLD §19). Step 0: a same-email repeat of `identity_created`/`tenant_pending`/`completed` reports progress (no CAPTCHA). Then CAPTCHA → rate limits (`RATE_*` via `WithRateLimits`; skipped on a payment resume) → validate → hash → lock → re-read: allocate (`payment_pending`), resume (`payment_pending`/`payment_action_required`/`payment_confirmed`, checked by `samePaymentDetails`), or — past payment — report state / `409 details_changed`, never a new `tenant_id`. `charge()` calls B-I1: action required → `202`; unknown outcome → keep handoff, `503`; declined/expired/rejected → delete handoff. Then PUB-1 (conflict keeps `payment_confirmed`), RP-2 (error keeps `payment_confirmed`), `HandoffOrchestrator.runI1`. Metrics use `mode="paid"`. The service is always constructed; only the route is gated by `PAID_SIGNUP_ENABLED`.

- **`internal/adapter/inbound/http/router.go`** — `PaidSignupEnabled` field in `RouterConfig` controls whether `POST /paid` is live or returns `404`. The 404 path is registered unconditionally so the route is never unmatched.
